## 关键设计决策

1. 三档分级（实测 322 道菜）：A 可换算 19 / B 有量无乘子 291 / C 无用量 12。档位写进出参，不假装都能换算。
2. 基准人数只来自入参与本地配置，不从上游取——上游 `servings` 恒为 1，原文“一份正好够 N 人”未被抽取。
3. 分页 + `facets` 全量聚合：保证 322 条口径可在分页下断言，facet 不随过滤条件变化。
4. 本地索引 `data/index/dishes.json`：启动时调一次 `getAllRecipes`（43.5KB）建索引，只存 id/name/category/tier；请求路径只用 `getRecipeById`（3.4KB）。搜菜全程走内存，不打上游。
5. `basket_get_recipe` 只接受 recipe_id，不接受菜名；菜名→id 解析只发生在 search，服务不替调用方选。
6. 批量接口用 `base_servings_overrides: Record<recipe_id, int>`，不用单一全局参数。
7. 新增错误码 `INDEX_NOT_READY`，禁止索引缺失时降级成空列表。

## 上游数据事实（复用价值高）

- `mcp_howtocook_getRecipeById` 参数名是 `query`；返回 `result.content[0].text` 是 JSON **字符串**，需二次 parse。
- `quantity`、`unit` 两列全为 null（0/4838），真实数值只在 `text_quantity` 里。
- 菜名带“的做法”后缀；218 道（67.7%）食材名重复；21 道 steps 为空；食材名污染如 `西红柿 =`。
- 版本的许可证不一致：package.json 是 ISC，README 写 MIT。商业分发前需确认。

## 课程叙事

三个教学点：MCP 服务调用 MCP 服务（编排）、外部数据不可信（防御层）、确定性计算与 LLM 的边界（数字不进 LLM）。
坑点清单：按份数直乘食用油得 8ml 而正确是 12ml（需先算鸡蛋个数），本题分水岭。
