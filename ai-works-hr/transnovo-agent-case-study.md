# 案例：构建器官移植市场情报智能体

> 整理日期：2026-11-10。依据本对话及原案例记录整理；未重新核验当日行业数据、知识库状态或报告交付情况。

## 一、任务背景

Ethan 是 TranSnovo 的 Marketing Leader，希望由 `transplant-mkt-intel` 持续收集器官移植情报，形成有来源、可比较、能支持市场决策的报告。

任务范围：
- **竞品**：XVIVO、OrganOx、Bridge to Life、TransMedics 的产品注册、研究、季度财报、股价及投融资。
- **领域**：异种器官移植、移植抗排异药物、移植后抗病毒感染的研究与 FDA 进展。
- **分析**：与 TranSnovo 产品比较优劣势，展示八季度销售、利润和股价趋势，分析投融资事件。
- **交付**：每月1日09:00（Asia/Shanghai）启动生成 Word 月报，保存到本地工作目录，完成后发送至 `xiaolan.yang@transnovo.com.cn`、`me@ethanhuang.com`；支持按需生成与发送。
- **知识与数据**：使用指定的 kb-agent 公司／产品知识，优先调用已连接 MCP，缺口由官方 API 和原文补齐。

## 二、任务过程

### 1. 建立研究与知识基础

原案例记录了 TranSnovo／ORS 与四家竞品的公司、产品、监管和临床证据整理，并逐步执行知识库写入。

研究强调三个边界：公司与品牌不能重复统计；监管必须对应产品、地域和用途；研究必须保留设计、人群及终点，不能把非劣效写成优效，或将生化指标改善外推为生存获益。

原案例最后记录：26条知识草稿中，13条通过审核；其余13项因自动摘要失真，改以1条校正版补充发布，形成14条正式知识，原13条错误摘要草稿仍未确认。分类接口曾将类型全部改成 `note`，异常未修复。**这些是原文件记录，不是本轮重新查询结果。**

### 2. 调研并验证数据获取渠道

先按研究、监管、财报、行情拆解需求，再核对现成 MCP、官方 API 与不可公开获取的信息。

| 能力 | 调研与验证结果 |
|---|---|
| 文献与试验 | BioMCP 文档确认可接 PubMed、Europe PMC、ClinicalTrials.gov；Europe PMC 与试验 API 实际请求均返回 HTTP 200，但未完成 BioMCP 端到端验收 |
| FDA | Drugs@FDA、PMA、510(k) API 实际请求均返回 HTTP 200；De Novo 及原始批准文件需另外补查，不能假定聚合服务覆盖完整 |
| 器械注册 | 医疗器械注册查询连接成功、启用状态确认；当轮尚未完成四家竞品业务查询验收 |
| 企业与学术披露 | 报告驿站连接成功、启用状态确认；财报结论仍须回到 SEC／公司 IR 原文 |
| 跨市场行情 | EODHD 官方 MCP 地址及认证要求确认；握手返回401，未授权取数，XVIVO 等个股覆盖未验收 |

同时校正主体口径：TransMedics 与 XVIVO 独立上市；OrganOx 无独立股价，Terumo 只能作为母公司背景；Bridge to Life 无公开交易股价及常规公开季报。**数据不存在或未公开，不是增加 MCP 就能解决。**

### 3. 明确后续能力缺口

优先补齐文献／试验、FDA 原文、财报与行情，再建立实体字典、证据存档、去重和变更监测。全球注册、移植量、支付报销及付费全文留作第二阶段。

连接成功、官方文档确认、上游 API 可访问和实际业务覆盖是四种不同状态，不能统称“验证通过”。宽泛检索还会混入牙科异种骨、肿瘤模型，必须增加器官、人群和排除条件。

### 4. 将业务需求转成智能体定义

采用 **Prompt Chaining＋RAG**：读取知识基线 → 收集证据 → 校验 → 分析 → 生成并检查 Word → 按授权发送。未采用开放式多智能体团队，避免不必要的交接与错误传播。

通过草稿确认，明确以下规则：
- 财务取最近八个已结束自然季度，未披露季度留缺；股价取八个完整自然季度，计算首季涨跌另取前季末基准。
- 原币、实际期间、报表及复权口径必须保留；厂家主张、研究结果与分析推断分开。
- 月报覆盖上月；按需报告截至运行时点。文件按生成日命名，同日重跑加时间，不覆盖旧稿。
- Ethan 预授权质量检查通过的月报发往两个固定邮箱；按需说“生成并发送”才发送，仅说“生成”不发送。
- 关键基线缺失、证据冲突、计算错误或 Word／附件失败时停止发送；发送状态不明不盲目重发。

用户确认路径、授权、失败处理及完整草稿后，写入项目级定义：

`.workbuddy/agents/transplant-mkt-intel.md`

校验确认 frontmatter 仅含 `name`、`description`，正文按 Role、Outcome、Capability、Knowledge、Stop 五段组织。另提交一条待审设计教训，未自动确认入库；其自动摘要存在授权表述偏差。

## 四、关键经验

1. **先定义证据边界，再分析优劣势。** 批准、临床终点、上市主体和财务期间混淆，会直接造成错误结论。
2. **写后回查。** 自动摘要和分类接口都可能失真，接口成功不等于业务成功。
3. **定义、连接、调度与运行分别验收。** 保存智能体文件不等于自动报告已经运行。
4. **自动发送必须有明确授权与质量阻断。** 固定收件人预授权不等于任意外发；“生成”与“发送”必须分开。

下一步：验收现有连接与知识基线，补齐文献和行情能力，试跑一份不发送的报告，通过后再配置并验证月度调度。
